# 실측 기록: AI 견적 읽기 정확도, 공표운임 최신성, KCCI 갱신 (2026-10-30)

기획서에 "아직 측정하지 않았다"고 적었던 항목 중 코드로 잴 수 있는 것은 모두 직접 돌려 보고 결과를 남겼습니다. 사람이 필요한 검증(담당자 인터뷰, 포워더 검수, 참여 기업 모집)은 이 문서의 범위가 아니며 마지막 절에 다음 단계로 적었습니다.

## 1. AI 견적 읽기 정확도

### 무엇을 쟀는가

- 대상: 운영 서비스의 `https://unim-lens.vercel.app/api/extract` (`main` @ `41eea8b`, 응답 모델 `gpt-5-mini-2025-08-07`). 2026-10-30 새벽(한국시간)에 실제로 호출했습니다.
- 견적 23건: 프로토타입의 예시 A, B, C 3건과 새로 만든 20건입니다. 한국어 메일, 영어 메일, 표를 붙여넣은 글, 탭 구분 표, 약어(O/F, BAF incl., THC, DOC, WFG, H/C, CFS, at cost, subject to, TBA, 실비), KRW, USD, EUR, JPY, 범위 금액, 퍼센트 요금, "21만원" 같은 한글 단위, 통화 없는 금액, OCR 오타(0/F, D0C), 서명과 전화번호가 섞인 메일, 장비별 요율이 한 줄에 둘 있는 견적을 섞었습니다. 항로는 미주 서안, 미주 동안, 북유럽, 지중해, 중국, 일본, 동남아이고 FCL과 LCL이 함께 있습니다.
- 형식: 글 15건, PNG 5건(Q04, Q08, Q12, Q16, Q17), PDF 3건(Q05, Q11, Q20). PNG와 PDF는 같은 원문을 headless Chrome으로 그려 업로드했습니다.
- 정답: 견적마다 비용 줄별로 이름, 허용 분류, 금액, 통화, 확인 필요 여부를 적었습니다. 채점 대상 줄은 141개입니다. "BAF incl."처럼 따로 뽑아도 되고 안 뽑아도 되는 줄은 선택 항목으로 두어 재현율과 정밀도 모두에서 벌점을 주지 않았습니다.
- 호출: 운영 서버의 제한(IP당 1분 5회)을 지키려고 13초 간격으로 한 건씩 보냈습니다. 실패한 호출은 없었습니다.

**모든 견적은 직접 만든 합성 견적입니다.** 회사명과 금액은 가상이고, 실제 고객 견적이나 스캔 품질이 나쁜 문서, 여러 쪽짜리 견적서는 들어 있지 않습니다. 정답도 작성자 한 명이 적었고 포워더 검수를 거치지 않았습니다. 따라서 아래 수치는 "형식이 깨끗한 견적에서 이 정도로 읽는다"는 하한 확인이며, 실제 견적에서의 정확도로 옮겨 쓰면 안 됩니다.

### 재현 방법

```sh
node tests/benchmark/render.cjs                       # PNG, PDF 만들기 (Chrome 필요)
```

견적과 정답은 `tests/benchmark/quotes.cjs`, 채점 규칙은 `tests/benchmark/score.cjs`, 응답 원본과 견적별 점수는 `tests/benchmark/results.json`에 있습니다. 매칭은 같은 금액, 같은 이름, 금액 없는 같은 분류 순서로 합니다. "지어낸 금액"은 AI가 낸 금액이 원문에 숫자로 없을 때로 셉니다(Q10처럼 만원 단위 정답은 따로 등록했습니다). Q17은 처음에 글로 보냈다가(5/5 정답) PNG 5건을 채우려고 PNG로 다시 보낸 결과로 바꿨습니다.

## 2. 공표운임 최신 공표분 조회

### 고친 내용

기존 코드는 최근 1년 범위에서 첫 50건만 받아 그 안에서 정렬했습니다. 2026-10-30에 운영 서버로 부산에서 로스앤젤레스를 조회하면 1,425건 중 화면에 나온 가장 최근 공표일이 **2025-11-05**였습니다. API가 오래된 공표부터 돌려주기 때문입니다.

`prototype/api/tariff.js`를 다음처럼 바꿨습니다.

1. 최근 90일로 먼저 조회하고, 결과가 없으면 180일, 365일로 넓힙니다.
2. 결과가 50건을 넘으면 첫 쪽과 마지막 쪽을 함께 받아 공표일 순으로 합칩니다. 응답이 어느 방향으로 정렬되어 와도 최신 행이 들어옵니다.
3. 조회 범위(`windowDays`)를 응답에 넣고, 화면 문구를 "최근 90일 공표 n건"으로 바꿨습니다.

같은 구간을 Preview 배포(`feat/verify-results`)에서 다시 조회하자 가장 최근 공표일이 **2026-10-29**로 나왔습니다.

## 3. 외부 AI 전송 동의

견적 올리기 창에 필수 체크 칸을 넣었습니다. 문구는 "업로드한 견적이 분석을 위해 외부 AI(OpenAI)로 전송되며 서버에 저장되지 않는다는 점을 확인했어요. 개인정보와 계약번호는 지우고 올릴게요. (필수)"입니다. 체크하기 전에는 "AI로 읽기" 버튼이 비활성이고, 버튼을 강제로 눌러도 요청을 보내지 않고 안내만 남깁니다. `tests/prototype.test.cjs`에 이 동작을 검사하는 테스트를 추가했습니다.

## 4. KCCI 최신값

- KOBC 공식 표(`gridList.do?mId=0304000000`)를 2026-10-30에 HTTP GET으로 받았습니다. 서버가 그린 HTML 표에 Current Index **2026-10-26** 열과 Previous Index 2026-10-19 열이 들어 있습니다. 이전 열 값은 기존 입력값(8,229, 11,590, 3,475, 3,835)과 같았습니다.
- 2026-10-26 값: 북미 서안 **8,267**, 북미 동안 **11,572**, 북유럽 **3,508**, 지중해 **3,945** USD/FEU. `prototype/data.js`를 이 값으로 바꿨고, 예시 B는 4,720달러 대 3,508달러로 약 +35%가 됩니다(이전 +36%).
- 공공데이터포털 15131881은 파일데이터(주간 XLS)이고 OpenAPI가 아닙니다. KOBC에도 공개 API 문서는 없었습니다. HTML 표를 읽어 자동 갱신하는 일은 기술적으로 가능하지만 공식 기계 판독 경로가 아니라 화면 구조가 바뀌면 깨집니다. 그래서 이번에는 자동 수집을 넣지 않고 수동 갱신과 확인 기록만 남겼습니다.
